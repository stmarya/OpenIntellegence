# AI Analyst

> **Status: unmerged feature work** — this document describes capabilities
> implemented in the `copilot/internal-orchestration-workers-case-create-report`
> branch and not yet merged to `main`.

## Overview

OpenIntelligence includes a RAG-grounded AI analyst that can generate
structured intelligence briefs for correlations, and a report pipeline that
creates tenant-scoped report records.  The internal worker for
`report.generate` is a request-creation step only — it does **not** invoke an
LLM or any external service.

## Internal action: `report.generate`

When a dispatched run includes a `report.generate` step the internal
orchestration worker:

1. Verifies the parent run is in `dispatched` state (approval gate).
2. Checks whether a `Report` row with `source_outbox_id = <idempotency_key>`
   already exists (idempotency / crash recovery).
3. Creates a tenant-scoped `Report` row with `status = "pending"` and
   `content_markdown = None`.  No report content is fabricated.
4. Records provenance citations from the run context so the origin is
   traceable even before generation starts.
5. Persists a receipt containing the new `report_id` in
   `AutomationOutbox.delivery_result`.

A separate generation pipeline (outside the scope of this worker) is
responsible for advancing `pending` reports to `generated` or `failed`.

### Report states

| Status      | Meaning                                                  |
|-------------|----------------------------------------------------------|
| `pending`   | Created by the worker; generation not yet started        |
| `queued`    | Queued for the LLM pipeline (future)                     |
| `running`   | Generation in progress                                   |
| `generated` | Successfully generated (content available)               |
| `completed` | Fully post-processed and delivered                       |
| `failed`    | Generation or post-processing failed                     |

The worker sets `pending`; it never advances to `generated` or beyond.

### Context fields recognised in `step_payload`

| Field      | Description                                          |
|------------|------------------------------------------------------|
| `title`    | Report title (falls back to `run_context.summary`)   |
| `template` | Report template key; defaults to `"generic"`         |

### Provenance citation format

The worker stores a citation entry in `Report.citations`:

```json
{
  "source": "automation_run",
  "run_id": "<uuid>",
  "playbook_id": "<uuid>",
  "source_type": "correlation",
  "source_id": "<uuid>"
}
```

This makes the origin traceable without revealing any intelligence content,
and satisfies the "unfalsifiable claim" policy for AI reports.

## No fabricated content

The worker explicitly sets `content_markdown = None`.  Any test or code path
that expects non-null content from the worker alone is a bug.  Report content
is only ever written by a generation pipeline that operates against live
intelligence data.

## RAG-grounded briefs

The `CorrelationAiBrief` model (migration `0005`) stores grounded briefs for
individual correlations.  These are generated by the `app/ai/reports.py`
pipeline, which is separate from the outbox worker.  The worker creates a
request token; the AI pipeline fulfils it.

## Idempotency

The `source_outbox_id` column on `Report` ensures that a worker restart or
lease expiry never creates duplicate report records.  On each processing
attempt the worker queries for an existing row before inserting.
